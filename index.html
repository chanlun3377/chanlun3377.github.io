Project 01 · Personal

校园电费智能监控告警系统

时间
2026.09 – 10
角色
独立开发
类型
个人项目 · 工具
链接
GitHub 仓库

01 — Context

游戏打到一半，宿舍又黑了

寝室经常因为忘记充电费，在打游戏、赶作业的中途突然断电。等想起来要充值，又可能撞上充值系统夜间维护，只能等到第二天。

我在 GitHub 上看到有人做“完美校园”电费告警，但现成方案在我们学校跑不起来——于是决定自己做一个。

02 — Problem

现成方案为什么不可用

  • 原方案依赖 GitHub Actions 或云服务器定时运行，而学校查询接口有阿里云 WAF，云服务器 IP 的请求全部被拦截（405）；
  • 原脚本用 shell + grep 解析 JSON，不同学校返回结构不同（roomlist / detaillist），字段一变就失效；
  • 阈值边界、空余额、中文编码等细节处理不好，就会误报、乱码，告警形同虚设。

03 — Process

重构，以及 AI 劝我放弃之后

  • 用 Python 重构数据层：json.loads 解析，兼容两种返回结构；浮点精确比较、空值过滤、原生 UTF-8 编码；
  • 通知层接入 Qmsg 酱 QQ 推送：每日 12:00、19:00 两次查询，余额低于 15 度触发告警，推送失败自动重试；
  • 关键转折：AI 带着我试了多家云服务器厂商，全部被 WAF 拦截，最后建议“到此为止”。我把前面所有线索重新串了一遍，自己提出改用本地住宅 IP + Windows 任务计划程序定时运行——一次走通；
  • 补上配置化适配层与优雅降级，并撰写 README 与踩坑记录。项目基于开源项目 zuwei522/perfect-campus_electricity-alert 重构，来源已在仓库注明。

04 — Outcome

持续运行的日常工具

系统部署后持续运行至今，覆盖照明、空调等多个房间，宿舍再没有出现过意外断电。代码以 MIT 协议公开，README 完整记录了部署步骤与云服务器被拦截的踩坑过程。

05 — Reflection

网上的代码固然优秀，但不一定适合自己的环境；AI 能快速给出方向，可方向必须自己过脑子。整个项目里真正决定成败的那一步——放弃云端、回到本地——是 AI 停下来之后，我自己把线索串起来想到的。

Project 02 · Internship

药王山品牌内容电商 0→1

时间
2026.07 – 08
角色
内容 / 宣发运营（独立完成）
类型
实习项目 · 内容电商
成果

01 — Context

一家第一次做线上的本草品牌

湖北药王山生态农业首次尝试线上化销售：没有公众号内容积累，没有线上视觉体系，也没有开店。我需要从 0 把内容、视觉和销售渠道一起搭起来。

02 — Problem

好产品，但用户看不懂

两款产品——植萃柔丝密丝养根皂（十二味本草）与艾君洁皮肤抑菌液（五味本草，李时珍医药集团生产）——背后是复杂的中医组方与熬制工艺流程。直接罗列成分，用户既不愿意看，也不会下单。内容要解决的，是“理解成本”和“行动意愿”两件事。

03 — Process

调研、翻译、拍摄、上架

  • 实地走访药田产地与生产一线，向公司负责人了解产品资料，结合公开资料补齐内容；
  • 选题与文案：从用户真实困扰（脱发、日常皮肤抑菌）切入，把君臣佐使的组方逻辑和工艺流程翻译成读得下去、可视化的内容；
  • 视觉制作：自己拍摄产品照片，用 Photoshop 完成两款产品的主图、品牌视觉与详情页长图；
  • 渠道搭建：按平台指引独立完成微店从 0 到 1 的开通、装修与商品上架。

04 — Outcome

被采用，并且拿到了真实结果

推文《你的洗发水，可能正在让你变秃！》取得 12% 点击率与 20% 转化率；两款产品的主图、详情页长图与微店全部被公司领导认可并实际投入使用。

05 — Reflection

好内容的本质是“翻译”——把专业的东西，翻译成用户愿意点开、看得懂、看完愿意行动的内容。这是我第一次在真实商业环境里验证“专业与数据 → 叙事 → 行动”这条主线，它确实成立。

最早被确认的“擅长”

采集数据 → 分析 → 可视化 → 讲成故事。这个公式在课堂上被我反复验证：从大一 SPSS 的四省体育报告，到《留在湖北的101个理由》交互 H5、《中国航天科创长图》，多门课程以满绩结课。我逐渐确认，自己最享受的环节始终是“让数据被人看懂”。
